4EvaluationDebug — the debugging tool
A shared, read-only renderer of a captured attempt’s {outcome, debug}, styled like the Editor’s Inject Tester: an Outcome pill, then a numbered colour-grouped step timeline (one group per evaluation parameter) with per-step success/fail/error pills, extracted-data dumps, and — for python — a Status/Exit/Duration table + STDOUT/STDERR. It shows the trace as captured at the moment of the action, deliberately not re-run. Opens as an overlay from any View evaluation / Debug control above. Every data dump carries a size & shape header — small values show in full, while anything over a (configurable) size cap is stored as a bounded preview at capture time, since MISP events run to several MB. That keeps the per-user buffer small and the view fast. (tabs below are mockup-only, to preview every trace kind)
